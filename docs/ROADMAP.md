## 2. فلسفة الدمج

اللعبة تصبح **حلقة مزدوجة**:

```
   ┌─────────────────────────── المتجر ───────────────────────────┐
   │                                                              │
   │   توصيلات → منتجات على الأرض → لمّها → ترتيبها على الرف     │
   │        ↑                                      ↓              │
   │   فلوس ← تحصيل الكاشير ← عميل يشتري من الرف ← طابور          │
   │        ↓                                      ↑              │
   │   ترقيات / موظفون / توسّع → سمعة أعلى → عملاء أكثر وصبر أطول  │
   └──────────────────────────────────────────────────────────────┘
```

- **اللاعب هو الكاشير والمنظّم في نفس الوقت.** لا يوجد كاشير آلي في البداية.
- **الرفوف هي المخزون الحقيقي.** العميل يأخذ منها فعلياً، فإذا فضيت يغضب ويقلّل السمعة.
- **التوصيلات تغذي الحلقة.** كل يوم تصل صناديق، وتفتحها بالـ E فتتناثر المنتجات.
- **السمعة هي المحرك.** تزيد عدد العملاء، صبرهم، والإكراميات.
- **الترقيات لا تخدم اللمّ فقط** بل الكاشير أيضاً (سرعة المسح، صبر أطول، كاشير مساعد).

## 3. الأنظمة الجديدة بالتفصيل

### 3.1 دورة اليوم (Day Cycle)

| البند | القيمة |
|---|---|
| بداية اليوم | 08:00 |
| نهاية اليوم | 20:00 |
| مدة اليوم الحقيقية | 6 دقائق (30 ثانية لكل ساعة لعب) |
| الإغلاق | تلقائي عند 20:00، أو يدوياً من لوحة الإدارة |
| ملخص اليوم | الإيرادات، العملاء المخدومين، الفاشلين، المنتجات المرتّبة، النظافة، الأجور، الإيجار، الصافي |
| اليوم التالي | زر واحد، والطلب يزيد |

- عدّاد الساعة في أعلى الشاشة بجانب رقم اليوم.
- عند الإغلاق: تجميد اللعبة، عرض الملخص، ثم بدء يوم جديد.
- الطلب اليومي = `4 + day*2 + store_level*2` عميل، مع حد أقصى للتواجد في نفس الوقت.
- كل يوم جديد: توصيلات مجانية، إعادة تعيين عدادات اليوم، وزيادة صعوبة بسيطة.

### 3.2 الكاشير (Cashier Loop)

**الموقع:** 4 مسارات دفع في مقدمة المتجر (الرابع يُفتح بترقية المتجر).

**التدفق:**
1. العميل يصل للطابور، ويقف على نقطة الانتظار.
2. عندما يصبح الأول، ينتقل إلى نقطة العميل ويضع منتجاته على السير.
3. اللاعب يقف خلف الكاشير، يصوّب على المنتج، ويضغط/يستمر بالضغط على **E** للمسح.
4. شريط تقدم يظهر فوق المنتج وفي لوحة الكاشير. عند الامتلاء: صوت بيب + السعر يطير.
5. بعد مسح كل المنتجات: يضيء قارئ البطاقة، واللاعب يضغط **E** على الكاونتر للتحصيل.
6. يُضاف السعر + الإكرامية، العميل يمشي، والطابور يتقدم.

**التفاصيل:**
- سعر البيع لكل قسم أعلى من سعر الترتيب (`SALE_PRICES`).
- الإكرامية = أساس + مكافأة سرعة + مضاعف السمعة.
- خطأ المسح (مسح منتج مرتين) مستحيل لأن المنتج يُحذف؛ لكن التأخير يقلل الإكرامية.
- صبر العميل يبدأ عند دخول الطابور، وينتهي بغضب إذا طال الانتظار.
- لوحة HUD تظهر تلقائياً عندما يكون اللاعب في منطقة الكاشير.

### 3.3 عملاء حقيقيون (Customer AI)

حالة العميل:

```
ENTER → TO_SHELF → SHOP → (TO_SHELF مرة ثانية) → TO_QUEUE → QUEUE
   → PAYING → LEAVING → DONE
                ↘ ANGRY → LEAVING
```

- كل عميل يختار 1–2 أقسام حسب الطلب، ويمشي عبر ممرات آمنة إلى الرف.
- يأخذ 1–3 منتجات من الرف فعلياً (`Shelf.take_product`).
- إذا كان الرف فارغاً: غضب فوري، سمعة −0.08، ويخرج.
- في الطابور: صبر مرئي (شريط فوق الرأس + لوحة الكاشير).
- عند انتهاء الصبر: يخرج غاضباً، سمعة −0.12، ويُحسب `lost`.
- العميل يحمل سلة/عربة، وسرعته تتأثر بالحمل.

### 3.4 التوصيلات والمخزون (Deliveries & Stock)

- منطقة توصيل ثابتة قرب المدخل الجانبي (رفوف كرتون + لافتة التوصيلات).
- كل يوم: 3 صناديق مجانية (أقسام عشوائية، 10–16 منتجاً لكل صندوق).
- فتح الصندوق بـ E: يتناثر المحتوى حوله على الأرض، ثم يختفي الصندوق.
- طلب توصيل إضافي من لوحة الإدارة: `$120` لكل صندوق.
- الرفوف لها سعة محددة، والعميل يستهلك منها، فالترتيب ليس للزينة فقط.

### 3.5 السمعة (Reputation)

مقياس 0.0 – 5.0 نجوم، يبدأ من 3.0.

| الحدث | التغيير |
|---|---|
| مسح منتج بنجاح | +0.004 |
| تحصيل سريع (أقل من 20 ثانية) | +0.02 |
| عميل يخرج سعيداً | +0.01 |
| عميل يخرج غاضباً (صبر) | −0.12 |
| رف فارغ أمام عميل | −0.08 |
| تنظيف قطعة قمامة | +0.006 |
| ترتيب 10 منتجات | +0.01 |

**التأثير:**
- حركة العملاء: `0.55 + reputation * 0.15` (3 نجوم = 1.0).
- صبر العميل: `32 + reputation * 7 + store_level * 4` ثانية.
- الإكرامية: `0.6 + reputation * 0.28`.

### 3.6 الموظفون (Staff)

| الموظف | سعر التوظيف | الأجر اليومي | الوظيفة |
|---|---|---|---|
| منظّف | $150 | $20 | يمشي لأقرب قمامة وينظفها (بدون كاش كامل) |
| مرتّب بضاعة | $250 | $30 | يلمّ منتجاً من الأرض ويرتّبه على الرف (50% كاش) |
| كاشير | $400 | $40 | يقف على المسار الرابع ويخدم طابوره تلقائياً |

- التوظيف من لوحة الإدارة، والفصل بزر ثانٍ.
- الأجور تُخصم في ملخص اليوم.
- الموظفون يظهرون كشخصيات حقيقية في المتجر بزي موحّد.

### 3.7 توسيع المتجر (Store Growth)

| المستوى | السعر | المزايا |
|---|---|---|
| 1 | — | 3 مسارات دفع، السعة الأساسية |
| 2 | $800 | فتح المسار الرابع + توظيف كاشير + عملاء +15% |
| 3 | $1,800 | أسعار بيع +12% + صبر +8 ثوان + توصيل إضافي |
| 4 | $3,500 | كاشير ذاتي يخدم عميلاً كل 20 ثانية + سمعة قصوى أعلى |

### 3.8 واجهة المستخدم (UI)

- **الشريط العلوي:** كاش، اليوم/الساعة، النجوم، العملاء المخدومون، التقدم، السعة.
- **لوحة الكاشير:** تظهر عند الوقوف خلف الكاونتر (منتجات متبقية، الإجمالي، الصبر، تلميح E).
- **لوحة الإدارة (U):** تبويبات — الترقيات / الموظفون / المتجر / الإحصائيات.
- **لوحة السمعة (R):** النجوم + آخر الأحداث + التأثيرات الحالية.
- **ملخص اليوم:** بطاقة كبيرة بعد الإغلاق.
- **أزرار الموبايل:** E (مسح/تفاعل)، Drop، Shop، إدارة، قفز، قرفصاء.

## 4. المعمارية التقنية

### 4.1 الملفات الجديدة

| الملف | الدور |
|---|---|
| `scripts/checkout.gd` | متحكم مسار الدفع: الطابور، السير، المسح، التحصيل، خدمة الموظف |
| `scripts/checkout_item.gd` | منتج على السير: تصادم، تقدم المسح، السعر، السحب |
| `scripts/customer.gd` | عميل حقيقي: تسوق، طابور، صبر، مغادرة |
| `scripts/delivery.gd` | صندوق توصيل قابل للفتح |
| `scripts/staff.gd` | موظف: منظف / مرتّب / كاشير |
| `docs/ROADMAP.md` | هذه الخطة |

### 4.2 تعديلات الملفات الحالية

- `game_state.gd`: اليوم، الساعة، السمعة، العملاء، الإيرادات، الموظفون، مستوى المتجر، التوصيلات، الأسعار، الإشارات.
- `main.gd`: بناء 4 مسارات، ربط الأنظمة، سبونر العملاء، دورة اليوم، التوصيلات، الموظفون، توجيه التفاعل.
- `shelf.gd`: `take_product()`، إعادة الأماكن الفارغة، سعة، مؤشر المخزون.
- `person.gd`: `nav_step()` للحركة الموجّهة، دعم المسارات غير المتكررة.
- `player.gd`: مسح بالاستمرار، تلميحات الكاشير/الصندوق، سكانر في اليد، منطقة الكاشير.
- `ui.gd`: الشريط العلوي الجديد، لوحة الكاشير، لوحة الإدارة، لوحة السمعة، ملخص اليوم، أزرار الموبايل.
- `README.md`: التحكم والأنظمة الجديدة.

### 4.3 قواعد التصميم

1. **لا كسر للحلقة القديمة.** اللمّ والترتيب والتنظيف والترقيات تبقى كما هي.
2. **كل نظام له إشارة وواجهة.** لا نظام صامت.
3. **كل شيء قابل للاختبار هيدلس.** دوال عامة (`begin_day`, `end_day`, `open_delivery`, `hire_staff`).
4. **لا تعقيد زائد في الفيزياء.** العملاء والموظفون `Node3D` بدون تصادم، والحركة عبر نقاط طريق.
5. **الأداء أولاً.** لا عمليات ثقيلة كل إطار؛ العدادات والتحديثات على فترات.
